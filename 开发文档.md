## 一、阅读须知

- 本文档面向**后续接手的 AI / 开发者**，所有设计必须能直接落地为代码；
- 文中提到的所有类名、方法名、配置键、文件路径都是**建议实现**，如无特殊需求请勿随意改名；
- 所有 HTTP 请求必须异步；所有 Bukkit API 调用必须回归主线程；
- 不要创建大量 `static` 可变状态，所有组件通过 `WorldmeMusicPlugin` 统一装配。

## 二、项目概述

`WorldmeMusic` 是一个 Bukkit 插件，实现 Minecraft 服务器内的网易云音乐点歌系统：

- 玩家指令搜索、点歌；
- 服务器维护全局 FIFO 播放队列；
- 通过插件消息通道向 `zmusic-mod` 客户端 Mod 发送 `[Play]<url>` / `[Stop]` 指令；
- 支持投票切歌；
- 管理员通过二维码登录网易云 VIP 账号，插件保存 Cookie 后用于获取高品质/完整歌曲 URL。

## 三、功能需求

### 3.1 玩家功能

| 命令 | 说明 |
|------|------|
| `/music search <关键词>` | 调用自建网易云 API 搜索单曲 |
| `/music add <序号>` | 将搜索结果中指定序号的歌曲加入服务器播放队列 |
| `/music queue` | 显示当前播放与队列 |
| `/music skip` | 发起/参与投票切歌 |
| `/music now` | 显示当前正在播放的歌曲 |

### 3.2 管理员功能

| 命令 | 说明 |
|------|------|
| `/music login qr` | 生成二维码图片链接，扫码登录网易云 VIP |
| `/music login status` | 查看登录状态 |
| `/music login refresh` | 刷新 Cookie |
| `/music logout` | 清除登录 |
| `/music skip force` | 强制切歌 |
| `/music stop` | 停止播放并清空队列 |
| `/music reload` | 重载配置 |

### 3.3 非功能需求

- 所有网络 IO 异步执行；
- 登录 Cookie 持久化；
- 玩家搜索会话运行时保存在内存；
- 全局仅使用一个 VIP 账号；
- 代码结构便于后续扩展代理端支持。

## 四、技术栈与工程约定

### 4.1 技术栈

| 项 | 选择 |
|----|------|
| 语言 | Java 21 |
| 构建工具 | Gradle Kotlin DSL |
| 服务端 API | `io.papermc.paper:paper-api:26.2.build.+`（compileOnly） |

### 4.2 工程约定

- **包名**：`top.worldme.music.*`；
- **主类**：`top.worldme.music.WorldmeMusicPlugin`；
- 除插件主类提供一个 `static WorldmeMusicPlugin getInstance()` 外，其他类避免 `static` 可变状态；
- 组件通过构造函数注入依赖；
- 配置键名与代码字段名保持一致；
- 对玩家的彩色消息使用 Bukkit `ChatColor` 或 `MiniMessage`（建议 `ChatColor` 简单实现）；

## 八、网易云 API 对接

### 8.1 接口列表

| 用途 | 端点 | 说明 |
|------|------|------|
| 获取二维码 key | `/login/qr/key` | GET |
| 创建二维码 | `/login/qr/create?key=xxx` | GET，返回 `qrurl` |
| 检查扫码 | `/login/qr/check?key=xxx&timestamp=xxx` | GET |
| 刷新登录 | `/login/refresh?timestamp=xxx` | GET |
| 搜索 | `/search?keywords=...&limit=N&offset=M&type=1` | GET，`type=1` 单曲 |
| 歌曲 URL | `/song/url/v1?id=...&level=...&timestamp=...` | GET |
| 歌曲详情 | `/song/detail?ids=...` | GET，取 `dt` 时长 |
| 歌词 | `/lyric?id=...` | GET，可选 |

### 8.2 请求工具类 `NeteaseClient`

所有方法返回 `CompletableFuture<JsonObject>` 或 `CompletableFuture<ApiResponse<T>>`。

核心方法：

```java
public CompletableFuture<List<Track>> search(String keyword, int limit, int offset)
public CompletableFuture<String> getSongUrl(long songId)
public CompletableFuture<Long> getSongDuration(long songId) // 通过 /song/detail 取 dt
public CompletableFuture<QrKeyResponse> qrLoginKey()
public CompletableFuture<String> qrLoginCreate(String key)
public CompletableFuture<QrCheckResponse> qrLoginCheck(String key)
public CompletableFuture<String> refreshLogin()
```

### 8.3 请求规范

- 使用 `java.net.http.HttpRequest` + `HttpClient`；
- 请求在异步线程执行；
- 所有 GET 请求附加 `timestamp=System.currentTimeMillis()`；
- 需要 Cookie 时，优先通过 Query 参数 `?cookie=<encoded>` 发送；
- 超时时长取自 `config.api.timeout-seconds`。

### 8.4 响应解析

使用 Gson 解析，安全取值：

```java
public static String getString(JsonObject obj, String key, String def)
public static int getInt(JsonObject obj, String key, int def)
public static JsonArray getArray(JsonObject obj, String key)
```

搜索字段映射：

```java
id: song.get("id").getAsLong()
name: song.get("name").getAsString()
artists: 拼接 song.getAsJsonArray("artists") 中每个元素的 "name"
album: song.getAsJsonObject("album").get("name").getAsString()
duration: song.get("dt").getAsLong()
```

## 九、二维码登录模块

### 9.1 设计目标

- 仅管理员可用；
- 全局一个 VIP 账号；
- 生成二维码 PNG 图片，通过内置 HTTP 服务器提供临时链接；
- 聊天框发送可点击链接给管理员；
- 登录成功后保存 Cookie。

### 9.2 流程

```text
/music login qr
  -> LoginManager.startQrLogin(Player admin)
       -> NeteaseClient.qrLoginKey() 获取 key
       -> NeteaseClient.qrLoginCreate(key) 获取 qrurl
       -> QRCode.create(qrurl) 生成 BufferedImage
       -> ImageUtil.createImage(qr, cellSize, margin) 生成 PNG
       -> QrImageServer.register(token, pngBytes)
       -> 发送链接 http://<host>:<port>/qr/<token>.png
       -> 启动 Bukkit 异步轮询任务
            -> 每 3 秒调用 /login/qr/check?key=...
            -> 801/802：继续
            -> 800：过期，停止
            -> 803：成功，保存 cookie，停止
```

### 9.3 服务器 IP 显示

使用 `Bukkit.getServer().getIp()` 与 `Bukkit.getServer().getPort()` 只能获取服务端监听地址，不一定能被管理员访问。建议：

- 优先从 `config` 读取一个对外地址字段，如 `login.qr-public-host`；
- 若未配置，回退到 `InetAddress.getLocalHost().getHostAddress()`；
- 端口使用 `config.login.qr-server-port`。

### 9.4 轮询处理

```java
// 在 Bukkit 异步任务中执行
Bukkit.getScheduler().runTaskTimerAsynchronously(plugin, () -> {
    neteaseClient.qrLoginCheck(key).thenAccept(status -> {
        Bukkit.getScheduler().runTask(plugin, () -> {
            switch (status.getCode()) {
                case 801, 802 -> { /* 继续 */ }
                case 800 -> session.expire();
                case 803 -> {
                    loginManager.saveCookie(status.getCookie(), status.getNickname(), status.getUserId());
                    session.complete();
                }
            }
        });
    });
}, 0L, intervalTicks);
```

## 十、与 zmusic-mod 通信协议

### 10.1 帧格式

```text
[1 字节 0x9A] + [UTF-8 文本]
```

Java 实现（不依赖 Netty）：

```java
private byte[] buildPayload(String text) {
    byte[] body = text.getBytes(StandardCharsets.UTF_8);
    byte[] payload = new byte[body.length + 1];
    payload[0] = (byte) 0x9A;
    System.arraycopy(body, 0, payload, 1, body.length);
    return payload;
}
```

### 10.2 命令

| 文本 | 含义 |
|------|------|
| `[Play]<url>` | 播放指定 URL |
| `[Stop]` | 停止播放 |

### 10.3 注册通道

```java
getServer().getMessenger().registerOutgoingPluginChannel(this, "zmusic:channel");
if (config.isSendAllmusic()) {
    getServer().getMessenger().registerOutgoingPluginChannel(this, "allmusic:channel");
}
```

### 10.4 发送逻辑

```java
public void broadcastPlay(String url) {
    String data = "[Play]" + url;
    byte[] payload = buildPayload(data);
    for (Player player : Bukkit.getOnlinePlayers()) {
        player.sendPluginMessage(plugin, config.getChannelZmusic(), payload);
        if (config.isSendAllmusic()) {
            player.sendPluginMessage(plugin, config.getChannelAllmusic(), payload);
        }
    }
}

public void broadcastStop() {
    byte[] payload = buildPayload("[Stop]");
    for (Player player : Bukkit.getOnlinePlayers()) {
        player.sendPluginMessage(plugin, config.getChannelZmusic(), payload);
        if (config.isSendAllmusic()) {
            player.sendPluginMessage(plugin, config.getChannelAllmusic(), payload);
        }
    }
}
```

### 10.5 玩家加入补发

`PlayerListener.onJoin`：如果 `MusicQueue` 当前正在播放，延迟 1 秒后向该玩家单独 `sendPluginMessage` 当前 `[Play]<url>`。

## 十一、播放队列设计

### 11.1 数据结构

```java
public class MusicQueue {
    private final Deque<QueuedTrack> queue = new LinkedList<>();
    private QueuedTrack currentTrack;
    private boolean playing;
    private int consecutiveFails;
    private BukkitTask nextTask;

    private final WorldmeMusicPlugin plugin;
    private final PluginConfig config;
    private final NeteaseClient neteaseClient;
    private final ZMusicMessenger messenger;
}
```

### 11.2 流程

1. `add(Track track, Player requester)`：
   - 检查队列长度是否超过 `config.queue.max-size`；
   - 如果队列为空且未播放，入队后立即播放；
   - 否则仅入队。

2. `playTrack(QueuedTrack track)`：
   - 设置 `currentTrack = track`；
   - 异步调用 `neteaseClient.getSongUrl(track.getId())`；
   - 成功后 `messenger.broadcastPlay(url)`；
   - 异步调用 `neteaseClient.getSongDuration(track.getId())` 获取时长；
   - 调度 `nextTask`：延迟 `durationMs / 50` ticks 后调用 `playNext()`。

3. `playNext()`：
   - 取消 `nextTask`；
   - 从队列头部取出下一首；
   - 有则 `playTrack(next)`；
   - 无则 `playing = false`，`currentTrack = null`，广播 `[Stop]`。

4. `stop()`：
   - 取消 `nextTask`；
   - 清空队列；
   - `currentTrack = null`；`playing = false`；
   - 广播 `[Stop]`。

### 11.3 切歌来源

| 来源 | 调用 |
|------|------|
| 歌曲自然结束 | `nextTask` 回调 |
| 投票通过 | `VoteSkipManager -> MusicQueue.playNext()` |
| 强制切歌 | `MusicQueue.playNext()` |
| 停止 | `MusicQueue.stop()` |

## 十二、投票切歌设计

### 12.1 数据结构

```java
public class VoteSkipManager {
    private final Set<UUID> voters = new HashSet<>();
    private boolean voting;
    private long startTime;
    private BukkitTask endTask;
}
```

### 12.2 流程

1. `vote(Player player)`：
   - 若当前未在播放，提示“没有正在播放的歌曲”；
   - 若已有投票且该玩家已投，提示“你已投票”；
   - 若已有投票，加入投票人并检查阈值；
   - 若无投票，创建新投票并启动 10 秒倒计时任务。

2. 阈值判断：

```java
int online = Bukkit.getOnlinePlayers().size();
return voters.size() * 2 > online; // 赞成 > 一半
```

3. 倒计时结束：
   - 若未通过，广播“投票未通过”；
   - 重置 `voting = false`。

### 12.3 强制切歌

`/music skip force` 直接调用 `MusicQueue.playNext()`，不受投票状态限制。

### 14.2 二维码图片 HTTP Handler

```java
HttpServer server = HttpServer.create(new InetSocketAddress(host, port), 0);
server.createContext("/qr", exchange -> {
    String path = exchange.getRequestURI().getPath(); // /qr/<token>.png
    String token = path.substring(path.lastIndexOf('/') + 1).replace(".png", "");
    byte[] image = images.get(token);
    if (image == null) {
        exchange.sendResponseHeaders(404, -1);
        return;
    }
    exchange.getResponseHeaders().set("Content-Type", "image/png");
    exchange.sendResponseHeaders(200, image.length);
    try (OutputStream out = exchange.getResponseBody()) {
        out.write(image);
    }
});
server.start();
```

## 十五、关键时序

### 15.1 点歌

```text
玩家 /music search 海阔天空
  -> MusicCommand 解析
  -> NeteaseClient.search() 异步
  -> 回调主线程
  -> PlayerSession 保存结果
  -> 玩家看到分页列表

玩家 /music add 1
  -> MusicCommand 从 PlayerSession 取索引 1 的 Track
  -> MusicQueue.add(track, player)
  -> 若队列空 -> MusicQueue.playTrack(track)
       -> NeteaseClient.getSongUrl(id)
       -> 成功后 ZMusicMessenger.broadcastPlay(url)
       -> 调度 nextTask
```

## 十七、风险与注意事项

1. **Cookie 安全**：`data/login.yml` 含网易云 Cookie，注意文件权限与 Git 管理；
2. **端口占用**：`login.qr-server-port` 可配置，被占用时插件应报错并停止二维码功能；
3. **headless**：无头 Linux 可能需 `-Djava.awt.headless=true`；
4. **API 缓存**：GET 请求加 `timestamp` 参数；
5. **Mod 不回状态**：服务端按歌曲时长估算切歌；
6. **版权合规**：仅供学习研究，勿用于商业用途。
